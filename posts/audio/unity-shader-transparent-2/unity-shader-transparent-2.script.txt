【钩子】
场景是白天的一棵树，叶子做成镂空，主渲染里叶隙清清楚楚。投影落到地面上，却是一整块实心的叶子形状的板。我第一反应是阴影贴图精度不够，加了分辨率，板还是板。真正的原因是阴影那条通道根本没采过 alpha，它只算光走多远。这一集讲透明物体的阴影，中心命题一句话：阴影贴图里只有距离、没有透明度，所以半透明阴影只能是近似，近似的方式决定了它看起来像什么。听完能拿到三件事：怎么把 alpha 接进阴影通道，抖动图案怎么用，以及最后为什么还是得做取舍。
阴影通道不知道透明，这是我们一切麻烦的起点。

【用了什么】
阴影投射通道是每个着色器里单独的一段，它不输出颜色，只把片元到光源的距离写进阴影贴图。这张图里存的阻挡结果是二值的，要么有光，要么被挡住，所以它没办法表达“挡住了三成”这种信息，这是这一集所有近似的根源。点光源用立方体阴影，其他类型的灯用普通阴影贴图，这是两条既有变体，我们这次要加第三条，让阴影通道也知道渲染模式。
抖动，英文 dither，用一张四乘四像素的图案图集裁剪片元，靠图案的疏密模拟介于全有和全无之间的密度。它和 alpha 测试的边界在判断依据：alpha 测试只看片元自己的 alpha，抖动还看片元在屏幕上的位置，所以同一个 alpha 的片元会有一部分被留下、一部分被剪掉。Unity 自带一张抖动模式图集，里面有十六种图案，从完全空的开始，每个连续的模式多填一个像素，填到七个之后开始反转，直到全部填满。这个填充顺序决定了密度是单调变化的，我们才可以拿它当渐变用。
还有坐标来源的边界。网格 uv 在这里不能用，因为它们在阴影空间里不一致；片元在屏幕上的坐标也不能由顶点程序显式输出，得在片元程序里声明一个带屏幕位置语义的参数，GPU 会直接提供。这个参数和裁剪空间位置在某些平台会冲突，后面细说。
阴影本质上是距离场，不是颜色。这一集要改的，是让这个距离场在透明的地方也保持正确。

【为什么用】
旧办法是阴影通道复用主渲染的逻辑，但不采样主纹理，于是透明区域照样投出实心影子。收益是把 alpha 带进阴影通道之后，镂空物体的影子形状对了，半透明物体的影子也有了密度感。
代价有三份：阴影通道要多采样一次主纹理；要按渲染模式拆出更多变体；抖动本身有视觉瑕疵，比如移动时整片影子在抖。默认走裁剪阴影，因为裁剪的结果是确定的，抖动需要人判断过才值得开。
什么时候不该用：不透明物体不要开，纯属浪费采样和变体；高频移动的半透明特效也不适合，抖动会闪。还有一类不该用：距离相机很远、影子只占几个像素的物体，加这套逻辑换不来可见的收益。
和抖动相比，镂空阴影是精确的，它的形状和主渲染一致，代价是硬边；抖动能给出密度感，代价是噪点。这两种都要，就只能做成可切换。
形状对得上，是这一集的最低要求。

【难在哪】
难点一，uv 该不该传进阴影通道。现象是阴影里拿不到正确的 alpha，要么全透过，要么全挡住。原因，阴影通道的顶点结构跟主渲染不一样，默认根本不传 uv。机制，用一个宏统一判断是否需要 uv，再用条件编译同时改三处：顶点结构体里的字段、顶点程序里的坐标变换、片元采样函数。三处必须同一个宏，漏一处就是编译错误或者错误采样。而且这个条件不能只看渲染模式，还要看主纹理的 alpha 有没有被平滑度占用；被占用了就不能拿它当透明用。这个判断散在三个文件里，只要有一处忘了同步，表现就是影子形状和主渲染对不上。
难点二，屏幕空间坐标不是网格坐标。现象是用网格 uv 采抖动图案，图案在影子里乱走。原因，网格 uv 在阴影空间里不连续，同一个物体的不同面接不上。机制，改用片元的屏幕坐标，让图案和阴影贴图对齐，因为阴影本来就是从光源视角渲染的，这样图案才稳定。但这个语义和裁剪空间位置的语义在某些平台上会映射到同一个位置，不能同时出现在一个结构体里，所以顶点和片元必须各定义一个独立的结构体。这不是风格问题，是编译和平台兼容问题。
难点三，密度和 alpha 的映射。现象是抖动出来的影子要么全黑，要么直接消失。原因，抖动图集是十六层，层坐标从零到一，每层间隔十六分之一。机制，把片元 alpha 乘以上限十五除以十六，得到这个片元该落在哪一层。不乘这个系数，alpha 为一的片元就落在图集之外，行为不确定。
三个难点其实都在回答同一个问题：阴影怎么知道透明。答案分两层：先知道该不该知道，靠一个宏统一判断；知道之后怎么表达密度，靠抖动的层号。第一层决定正确性，第二层决定观感。

【从0到1】
这一集只展开八个关键块，属性声明之类的样板略过。
这一集的做法可以看成一条链：先让阴影通道拿到 alpha，再让它知道渲染模式，最后让它用抖动表达密度。每一步都要在帧调试器和画面上各验证一次，只在编辑器的材质球上点头，是看不出问题的。
里程碑一，给阴影通道接 alpha。目标是镂空物体的影子也镂空。做法是先把色调、主纹理、裁剪阈值和渲染设置拷进阴影那段代码，拷贝声明这部分是样板，略过。再加一个宏判断：当渲染模式是镂空、并且主纹理 alpha 没有被平滑度占用时，定义需要 uv。结构体里用条件编译加一个 uv 字段，顶点里用条件编译做坐标变换，采样函数里用同一个宏包住 alpha 采样，最后在片元里按镂空模式裁剪。裁剪要放在所有可能提前返回之前，否则某些分支会跳过它。
为什么强调 alpha 不能被平滑度占用：一旦主纹理 alpha 拿去当平滑度，这里再采一次就会把平滑度当透明，阴影会碎得很奇怪。这个冲突在上一集就埋下了，现在才显形。
结构体那一处还有个容易漏的分支：立方体阴影需要一组光向量，普通阴影不需要，所以字段也要用条件编译分开。
顺带说一句，原来的阴影通道已经有两套变体，一套给点光源的立方体阴影，一套给其他灯，我们这次是在它们之上再加第三个变体，专门覆盖需要采样的渲染模式，公共部分放一起改。
验证，把阈值从零拖到一，地面上的影子跟着被削掉。到这里，镂空的树终于在地上有叶隙了，这是整个改造里最直观的一次验证。
里程碑二，让阴影通道知道其他模式。目标是淡入淡出和全透明模式下，阴影也有对应处理。做法是在阴影通道的着色器里加上三个渲染模式的关键字，再根据模式定义一个半透明阴影的宏。关键字必须和主渲染用同一套名字，不然面板切了模式，阴影这边收不到信号。这里常见的坑是关键字只写了两个，淡入淡出模式匹配不上，阴影就退回了裁剪分支，补成三个才生效。
这一步之后，问题变成了：即使知道了要半透明，也裁不出半透明。因为裁剪只有留和丢两种结果。
里程碑三，抖动阴影。目标是让影子有密度而不是硬边。做法是声明一张三维的抖动遮罩纹理，必须用三维采样器声明，真实的图案存在不同的层里。片元里按屏幕坐标和层号采样，取 alpha 通道，减去一个较小的值后裁剪，顺序不能反。为什么要写成三维采样器：图案是按层存的，两维采样读不到层号，取回来的东西没有意义。
层号先固定成十六分之一，只为看到图案；这时必须把屏幕坐标乘一个很小的系数，才在聚光灯下看清铺开的图案，系数太大图案会碎得看不清整体。第三层坐标就是模式选择，零到一之间以十六分之一为步进，正好对应十六种图案。验证，把系数调大或调小，图案的疏密跟着变。
里程碑四，用 alpha 驱动密度。目标是影子密度跟着物体透明度走。做法是把第三层坐标换成 alpha 乘以十六分之十五，再把屏幕坐标乘零点二五对齐图集密度。乘十六分之十五而不是乘一，是因为层号最大只能到十六分之十五，超出去就没有图案了；透明度为一的片元正好落在最实的那一层。
效果能看，但不完美，取决于抖动图集的分辨率，越密越好，硬阴影和软阴影下的表现也不一样。所以这类方案更适合当过渡方案：近景、静态、轻微透明的物体可以开，角色和特效不开。还有一个明显的视觉问题，物体一移动，整片影子都在抖，密集恐惧。这不是参数没调好，是方法本身的问题：图案跟着屏幕坐标走，物体一动，采样位置就整体漂移。
里程碑五，做成可切换。目标是既想要实体影子，也想临时用抖动影子。做法是阴影通道再加一个关键字，默认走裁剪阴影，打开才走抖动；同时让半透明阴影的宏只在打开时才定义，没有启用就回退到裁剪阴影。
面板上加一个开关，只在淡入淡出和全透明模式下显示，关闭时让裁剪阈值滑块重新出现，否则面板上会缺一项。开关的值写进材质，不写进 Shader，这样同一个 Shader 的不同材质可以各自选。这个细节很容易漏，表现是关掉半透明阴影后，想调阈值却找不到控件。互斥的逻辑要写在一处：开关打开就定义半透明阴影的宏，关闭就退回镂空裁剪，两条路径只能走一条。另外，镂空模式下本来就不该出现这个开关，因为镂空的阴影是精确的，没有密度可调。验证，切一次开关，帧调试器里阴影批次的指令条数会变。
五个里程碑走完，形状和密度这两件事都有了，但都是近似。后面那节踩坑，基本都是这条链上某一处没接住。

【踩坑与边界】
坑一，宏的名字前后不一致。症状是编译报错，或者 uv 永远是零。根因，条件编译的宏在三处拼写不同。修复，统一宏名，只在一处定义，其余处只判断。
坑二，顶点结构体里同时放两个位置语义。症状是某些平台上阴影全黑。根因，屏幕坐标语义和裁剪位置语义映射到同一位置。修复，拆成两个结构体，顶点一个、片元一个。
坑三，抖动图案频率不对。症状是影子看起来是规则网格噪点，像纱窗。根因，屏幕坐标的缩放系数和图集密度不匹配。修复，按图集密度调系数，先放大看清，再收回去。
坑四，抖动带来的移动闪烁。症状是物体一动，整片影子在爬。根因，图案跟着屏幕坐标走，而不是跟着表面走。修复，这属于方法本身的限制，只能降低使用频率，或者干脆切回裁剪阴影。
坑五，关键字写少了。症状是某个渲染模式下的阴影还是实心。根因，阴影通道的关键字数量比主渲染少一个。修复，三处关键字保持一致。
坑六，以为阴影贴图能存部分遮挡。症状是反复调参数，密度却怎么都不对。根因，阴影贴图只存距离和有无，没有余量表达百分比。修复，接受它只能近似，把预算花在刀刃上，比如只给主角和近景物体开。
坑七，阴影通道和主渲染的关键字不同步。症状是面板上改了模式，影子形状不跟着变。根因，两处各写各的关键字。修复，把关键字开关集中在面板一处，两边共用同一套名字。
边界：阴影贴图只存距离，真正的连续半透明衰减做不到；抖动是二值近似，效果依赖屏幕分辨率；软阴影下图案更糊。半透明阴影的开关只管阴影，不影响主渲染的透明效果，两边要分别调。镂空阴影是可以精确做的，代价是硬边；抖动阴影能出灰度感，代价是噪点和闪烁。这两者之间没有免费选项。
没有免费选项，这就是它的边界。形状能精确，密度只能近似，两个都要，就只能在两者之间切。

【收束】
三句话：阴影通道默认不知道 alpha；把它接进来要靠一个宏统一三处；密度只能靠抖动近似。三句话分别对应上面的接入、变体和密度三个里程碑。该用的时候是镂空和轻微透明的物体需要正确投影；不该用的时候是高频移动的半透明特效，抖动会闪得难受。
