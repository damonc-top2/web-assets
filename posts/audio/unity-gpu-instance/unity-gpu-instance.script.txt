【钩子】
我在场景里生成了五千个球，想看看帧率。统计面板跳出来，五千多个批次。帧率掉到个位数。
我以为是球太密。换成立方体，数字没变。我才意识到问题不在几何复杂度，而在每一帧要告诉 GPU 多少件事：画什么网格、用什么材质、用哪个变换矩阵。
这篇要回答的命题是：GPU 实例化到底把哪一部分开销省掉了，着色器又必须配合到哪一步。
听完能拿到三件事。第一，为什么打开实例化后所有球会叠在同一个位置。第二，每批最多能塞多少个实例，这个数是怎么算出来的。第三，颜色各不相同的时候怎么还能合批。

【用了什么】
先划清边界。Unity 有三种合批手段。
静态合批是把多个静态网格合并成一个更大的网格。它只对同材质的物体有效，代价是要存更多网格数据。
动态合批是运行时对视野内的动态物体做同样的事。它只适用于小网格，网格一大，合并本身的开销就超过收益。
第三种就是 GPU 实例化，也叫几何实例化。它跟动态合批一样是运行时针对可见物体，但目标不同：它要让 GPU 一次画出同一个网格的多个副本。
所以它不能合并不同的网格，也不能合并不同的材质。它省的不是几何数据，而是重复的绘制指令和重复的状态设置。
这一点是理解后面所有限制的钥匙。

【为什么用】
旧办法的痛点很具体。每个球都要一次绘制调用，还要传一次网格和材质属性。五千个球就是五千次。
新办法的收益：同一个网格、同一个材质的物体，一次绘制就能画一批。
代价有三条。
第一，必须改着色器。Unity 不会自动做这件事，默认情况下实例化是关闭的，材质上还得显式勾选。
第二，属性数据要占用缓冲区。缓冲区有大小上限，这直接决定了批次大小。
第三，属性一变就得走属性缓冲区。用普通方式改材质颜色，合批立刻失效。
什么时候不该用：物体种类多、材质各不相同、或者数量只有几十个。这时候实例化带来的复杂度不划算。

【难在哪】
难点一：合批之后，所有球用了同一个矩阵。
现象是最该看得见的位置信息没了。五千个球全叠在原点附近，或者更准确地说，全用了这一批里第一个球的变换。画面里只剩下几个球。
原因是同一批里所有球的矩阵现在是作为一个数组送进 GPU 的。不告诉着色器该用哪个数组索引，它当然一直取第一个。
机制上，每个实例对应的数组下标叫实例 ID，由 GPU 通过顶点数据传进来。它一般是一个无符号整数，用专门的实例 ID 语义声明。

难点二：批次的容量是被缓冲区卡住的。
现象是批次数量跟我算的不一样，想的是一批五百个，实际只有一百二十五。
原因是缓冲区上限因平台而异，而且 Unity 会在某些图形接口下主动缩水。
机制上，一个实例需要两个矩阵：物体到世界，世界到物体，后者用来转法线。每个矩阵十六个浮点，每个浮点四字节，合起来六十四字节，两个就是一百二十八字节。
桌面显卡按每个缓冲区六十四 KB 算，能放五百多个。所以默认数组大小定在五百。可以改，但改成五百一十二会触发断言失败，实际上限是五百一十一。
移动设备可能只有十六 KB。Unity 在面向 OpenGL ES 三点零、OpenGL Core 或者 Metal 时，会把上限除以四。所以我在编辑器里用 OpenGL Core，批次上限就变成一百二十五。
五千除以一百二十五，正好四十批。这就是那个数字的来源。

难点三：颜色一变，合批就散了。
现象是给每个球随机上色，批次立刻从四十涨到五千。统计面板里状态切换次数也跟着炸。
原因是给每个球赋一个新材质，等于每个球都有自己的着色器状态。
机制上，合批的前提是状态一致。要打破这个前提去改颜色，就得换一条路：把颜色做成每个实例的独立数据，塞进同一块缓冲区。

【从0到1】
里程碑一：把问题摆出来。
目标是一个可复现的测试场景。做法是挂一个组件，对外暴露一个预制体和实例数量，默认五千，还有个半径参数默认五十。
启动时循环实例化，位置取单位球内的随机点再乘半径，挂到同一个父节点下。然后看统计面板。
用前向渲染路径，去掉背景和相机特效那两个绘制，剩下的就是纯球的开销。
把球换成立方体，数字几乎不变。这证明了瓶颈不在顶点数，而在绘制次数。
验证方法：在这个阶段先别改着色器，先让数字难看，后面才有对照。

里程碑二：打开实例化开关。
目标是让材质上出现那个勾选框。
做法是在着色器扩展面板里加一个高级选项分区，在里面调用材质编辑器的启用实例化字段。这个开关只有在着色器本身支持实例化时才会显示。
然后加一条实例化的多编译指令。它会生成一批着色器变体，其中一个关键字就是实例化开启。
验证方法：回到场景，批次应该从五千多掉到四十出头，帧率也上去了。但画面一定是错的，所有球挤在一起。这一步只是证明了机制在跑。

里程碑三：让每个实例拿到自己的矩阵。
目标是把实例 ID 用起来。改三个地方。
第一处，在顶点数据结构里加一个实例 ID 字段。Unity 提供了一组宏：支持实例化时展开成真正的声明，不支持时什么也不做。所以同一份代码在两种情况下都能编译。
第二处，在顶点程序最开头，调用设置实例 ID 的宏。必须是最先，因为后面的代码都依赖这个全局下标。
第三处，也是我觉得最巧的一处：不用改任何变换代码。
原因是 Unity 的实例化包含文件用宏把物体到世界矩阵重新定义了，改成了一个数组。原本取单个矩阵的地方，现在取数组里对应下标的那个。这算是一种取巧的宏替换，但它让所有既有着色器代码不用改一行就能兼容。
代价是调试时很难看出来。我在代码里找不到任何数组访问，因为它在宏里。
验证方法：球应该各归各位。如果还是叠在一起，八成是设置实例 ID 那一步没放在最前面。

里程碑四：让颜色也变成每实例数据。
目标是不换材质也能改颜色。
先看正确的数据来源。不能用材质，要用材质属性块。它是附在渲染器上的一小份属性覆盖，设置好颜色后传给渲染器，而不是直接改材质。属性块在循环外建一次，循环里给五千个球每个渲染器各设一份，材质还是那一个。
但要让它在 GPU 端生效，着色器得声明一个实例缓冲区。
声明方式跟定义结构体类似，只是语法因平台而变。Unity 用一对开始和结束的宏把差异抹平，没启用实例化时它们什么都不做。
把颜色变量从这个缓冲区里定义，用定义实例属性的宏替换普通声明。
然后颜色就变成数组了。要读到对应元素，片段程序里也得知道实例 ID。所以插值器里要带上它，顶点程序里把 ID 从顶点数据复制到插值器，这一步也有对应的宏。
片段程序开头再设置一次实例 ID，让它全局可见。
最后取值的方式要改。没实例化时直接读颜色，实例化时读数组的当前下标。Unity 给了一个访问宏，两种情况都能用。
这里有个版本坑。从 2017.3 开始，这个访问宏要两个参数：先是缓冲区名，再是属性名。教程按旧版本写的单参数形式，在新版本里会编译报错。
验证方法：颜色应该随机了，批次应该回到四十。如果批次还在五千，说明属性块没设置成功。
还有一点：能这样做的不只是颜色。浮点数、矩阵、四分量向量都可以。纹理不行，要换纹理得用纹理数组，然后把索引放进实例缓冲区。
缓冲区也不是免费的。它按三十二位分块，所以一个浮点和一个四分量向量占一样大的空间。属性越多，能吃下的实例越少。所以只把真正需要每个实例不同的属性放进来。

里程碑五：把阴影和延迟路径补上。
目标是让阴影也跟着实例化。
做法是在阴影投射通道里加同样的实例化指令，同时加上实例 ID 的声明和设置。不加的话，阴影仍然是一个物体画一次。
多光源也一样。实例化只在基础通道和阴影通道里开了，其他光源的附加通道没开，所以那些光下的合批不生效。
要跟多光源一起用，只能切到延迟渲染路径，再把同样的指令加到延迟通道里。
验证方法：打开软阴影，把阴影距离拉到能覆盖所有球，看批次有没有回升。再关掉主光，加几盏聚光，对比开与不开延迟路径的批次差。
顺带一个陷阱：有个选项声称能假设所有实例等比缩放，从而省掉世界到物体矩阵。听起来能省一半缓冲区，但在 2017.1 里它其实什么都不做。函数行为改了，第二个矩阵数组照样存在。

里程碑六：LOD 组也要能合批。
目标是把带 LOD 的物体也纳入实例化。
现象是颜色解决了，LOD 相关的批次还是散的。Unity 能把 LOD 颜色相同的球合在一起，但这不是我要的效果。
原因是 LOD 淡出用的渐变变量还是全局的，每个实例值不同就没法合成一批。
做法是给需要实例化的每个通道加上 lodfade 这个实例化选项。它会让 Unity 的着色器代码用数组替换那个渐变变量，每个实例取自己的值。
验证方法：批次应该不再按 LOD 分级拆开。

【踩坑与边界】
坑一：以为实例化会合并不同网格。
症状是换了模型之后批次又炸了。根因是它只能画同一网格的多个副本。修复：不同网格要另外做图集或者换方案。
坑二：用材质改颜色。
症状是颜色对了，批次没了。根因是每个材质一份状态。修复：用材质属性块加属性缓冲区。
坑三：在错误的位置设置实例 ID。
症状是画面全乱，或者所有实例共享同一个变换。根因是全局下标还没赋值就被用了。修复：放在顶点程序第一行。
坑四：以为批次大小是固定的。
症状是同一份工程在手机和电脑上批次数差四倍。根因是缓冲区上限不同，加上 Unity 对某些图形接口主动除以四。修复：不要按桌面数字去设计预算。想强行统一上限，有对应的实例化选项可以关闭自动缩减，但那可能在移动端直接出问题，慎用。
坑五：访问宏的参数个数对不上。
症状是升级引擎后着色器编译失败。根因是 2017.3 改了宏的签名。修复：按新版本传两个参数。
性能边界：实例化节省的是绘制调用和状态切换，不节省像素。五千个球如果都占满屏幕，瓶颈会立刻从绘制转到填充率。它也不减少三角形数量，几何本身的复杂度一点没变。

【收束】
三句话。
实例化省的是重复的绘制指令，不是几何数据。
着色器要做的只有一件事：把实例 ID 从顶点数据搬到需要它的每一个地方。
矩阵、颜色、渐变值，全都是同一个套路。
什么时候该用：同网格同材质、数量成百上千的时候。
什么时候不该用：物体只有几十个，或者材质各不相同的时候。
下一期换个方向。一块平的四边形，怎么靠纹理坐标偏移，让人看出凹凸的深度。
