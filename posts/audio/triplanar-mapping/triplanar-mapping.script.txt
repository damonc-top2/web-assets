【钩子】
我在做一个运行时生成的地形，网格是程序化拼出来的，顶点里根本没有 UV。贴图一上去，要么被拉伸成一整片颜色，要么相邻的面之间完全错位。纹理映射的常规做法依赖每个顶点存一对 UV 坐标，可程序化几何体给不出这个坐标，地形和洞穴系统尤其如此。这篇是我的解法复盘：三平面映射。中心命题一句话：既然没有 UV，那就用世界位置在三个正交平面上各投影一次，再用法线当权重把三次采样平滑地混合起来。听完之后，应该能独立走出这条路：怎么让老的包含文件在没有 UV 时也编译得过，怎么把表面属性收成一个统一结构，怎么处理投影接缝和纹理镜像，以及为什么法线贴图在这里必须手工换轴。

【用了什么】
三平面映射，英文是 triplanar mapping，属于表面属性获取这一层。正常流程是顶点带 UV、片段按 UV 采样。它跳过 UV，直接用世界位置或者对象空间位置当纹理坐标。一个三维位置配一张二维贴图，必须丢掉一个维度，这等于把纹理投影到三维空间的一个平面上。丢 Z 留下 XY，就是沿 Z 轴投影；丢 Y 留下 XZ，就是沿 Y 轴投影，这也是地形常用的平面映射；丢 X 留下 YZ，就是沿 X 轴投影。
边界要说清楚。它不是 3D 纹理，3D 纹理也能解决无 UV 的问题，但存储空间大得多，而且要调得好看很难，所以我还是用 2D 贴图投影三次。它也不是切线空间的东西，Unity 表面着色器给的是切线空间，我这里全部在世界空间做，所以切线空间法线贴图必须自己显式转换，这一步没有现成矩阵可用。它也不是贴花的替代品，贴花可以在局部叠加细节，三平面是在全局解决坐标来源。

【为什么用】
旧办法的痛点有三个。一是程序化几何体没有 UV。二是即使能展 UV，运行时生成的地形或者洞穴做一次正确的展开，成本很高，接缝还多。三是任何依赖 UV 的效果都得跟着改，细节贴图、视差、顶点位移，它们全都需要一对 UV 才能工作。
新办法的收益是，只依赖世界位置和法线，任意形状都能贴，展 UV 这一步直接消失。还有一个附带收益是切线：当没有法线贴图、没有细节法线、没有视差的时候，切线空间的插值器可以整个去掉，顶点程序不用算切线和副法线，片段里的法线初始化简化成一次归一化。对于本来就没有 UV 的网格，切线往往也没有，这个收益是实打实的。
代价同样清楚。最直接的是采样量三倍，反照率、法线、打包属性贴图，每个都要采三次。其次是法线贴图不能直接用，必须经过换轴、镜像翻转，再和表面法线做一次混合，否则球体会被贴成立方体。再次是镜像和重复会变明显，必须额外处理。最后，UV 和切线相关的分支变多，着色器变体和包含文件之间的依赖都在涨。
什么时候不该用：表面基本轴对齐的物体，比如建筑的地板墙面，普通 UV 更省也更准；需要严格按 UV 对齐的图案，比如带序列号的贴图，三平面给不了这种控制；移动端采样预算已经很紧的场景，三倍采样要慎重。反过来，程序化地形、洞穴、任意形状的道具，它是首选。

【难在哪】
难点一，三个投影之间的接缝。现象是，如果每次只挑当前最合适的那一个投影，接缝会非常硬，因为最合适是一个离散选择，越过某个角度就整块跳过去。原因是中间没有过渡。机制是用法线做权重：取法线三个分量的绝对值，再除以三者之和，让权重总和恒为一，三个投影按权重连续混合。这样一来，只有当某个分量明显占优时，那个投影才真正主导。
难点二，法线的坐标系是错的。现象是打开法线贴图之后，整个表面糊成蓝色。原因是切线空间法线的 Z 通道存的是相对于表面的上方向，而三个投影里只有 Z 投影的轴向和这个上方向一致，另外两个投影的上方向分别是 Y 和 X。机制是换轴，X 投影把横轴和深浅轴对调，Y 投影把纵轴和深浅轴对调，Z 投影不动。换完还有第二个问题，法线和真实表面没有关系，球体上的法线看起来像立方体，所以还要和表面法线做一次 whiteout 混合。
难点三，权重调节是非线性的。现象是默认权重下混合区太宽，材质糊成一片，看不出电路和大理石的边界。原因是法线接近四十五度时，三个权重都接近三分之一，谁也没占优。机制是三种手段叠加：先从所有权重里减去一个偏移，小的权重受影响更大；再把权重取幂，大的更大、小的更小；最后引入高度，让贴图里的高度数据也参与竞争，并且用强度参数限制它的介入程度。
这三个难点其实在回答同一个命题：三平面映射的核心不是投影，是混合。

【从0到1】
里程碑一，让老的包含文件在没有 UV 时也能编译。目标是同一套代码，有 UV 和没 UV 都能跑，而且默认行为不变。关键语义是，我用一个宏表示关闭默认 UV，插值器里的 UV 声明包在这个宏的条件里，这样顶点程序没有 UV 可以传。但麻烦在于有多个函数默认插值器一定带 UV，所以我加了一个取默认 UV 的函数，宏打开时它返回零，否则返回原来的 UV。再把这个函数包成一个可覆盖的宏，默认指向它自己，外部可以先定义自己的实现。这一点和反照率函数一样，覆盖定义必须写在包含文件之前。原来所有取 UV 的地方，全部改成走这个宏。
同一件事在顶点程序里要再补一遍：纹理坐标变换跳过，默认的顶点位移也跳过，因为它采样的正是主 UV。视差效果同样依赖默认 UV，UV 不可用时整段跳过。阴影通道不需要特殊处理，因为它根本不关心不透明几何体的表面属性。
切线这块我用一个宏来收口：只有默认法线贴图、细节法线或者视差处于活动状态时，才需要切线空间。需要的时候才声明切线和副法线插值器，才在顶点程序里计算它们，不需要的时候片段的法线初始化就只剩一次归一化。如果切线不是逐片段重建，副法线还要用切线的符号位来构造。验证方法很朴素：拿一个没有 UV 的网格，能编译、能渲染、颜色不黑，就说明这套分支是对的。
里程碑二，把表面属性收成一个统一契约。目标是包含文件不再关心属性是怎么来的，它只负责用。这正是 Unity 表面着色器的思路，靠一个函数把所有属性一次填完。我新建了一个只放表面数据的文件，里面两个结构体：表面数据包含反照率、自发光、法线、透明度、金属度、遮蔽和光滑度；表面参数包含法线、位置和 UV，也就是自定义函数拿到的输入。表面数据单独成文件，是因为其它代码需要在包含别的文件之前就能用到它，但它自己又依赖光照输入，所以它也在光照输入里被包含。
在片段程序里，我在视差之后、使用透明度之前，新建一个表面数据变量，按默认路径逐项填好，并且把法线初始化提前到填表面之前。裁剪改成读表面数据的透明度，最终的片段颜色改成读表面数据，写几何缓冲时也一样，间接光函数加了一个表面数据参数，因为函数内部要用光滑度和遮蔽。
再往上一层，就是允许外部定义表面函数。我在片段程序里加了分支：如果定义了自定义表面函数，先把表面数据填成一组默认值，再用插值法线、世界位置和 UV 组成参数结构，调用那个函数。因为它可能改法线，调用完之后我把表面法线写回插值器里的法线，这样后面所有用到法线的代码都不用动。反照率函数也有同样的默认定义，保证老着色器不受影响。
验证方法：先把表面函数写成只输出法线，画面应该是一张标准的世界空间法线图，红绿蓝分布在三个方向上。
这一层做完，回到中心命题：混合的入口准备好了，接下来只差把位置变成 UV。
里程碑三，三对 UV 与三次投影。目标是把位置变成三对像样的纹理坐标。关键语义是，整段逻辑单独放进一个结构体和一个函数：三个坐标来源分别是 ZY、XZ、XY。这里有个容易被忽略的细节，沿 X 轴投影时如果直接用 YZ，纹理整体会旋转九十度，所以要换成 ZY 的顺序才符合预期方向。然后最直接的做法是三次采样取平均。
验证方法：用一个球体和一个立方体，把平均后的反照率当颜色看，三个方向上的纹理密度应该一致，明暗交界处能看到混合出来的过渡带。
里程碑四，法线权重、镜像与重复。目标是让最贴合表面的那个投影真正主导。关键语义是，权重取法线绝对值的归一化，因为表面可能朝向负方向，权重不能是负的。这时还要处理镜像：轴对齐的立方体会有一半的面用到镜像后的纹理，带数字的测试贴图上一眼就能看出来。修复方式是条件性地把某个坐标取负：法线的 X 或 Y 分量为负时取负 U，Z 分量反过来，在为正时取负。这会在某个分量为零的地方产生接缝，但那里权重也正好是零，所以看不出来。
再一个问题是重复。同一个纹理投影三次，球体上会看到明显的重复，本该是四十四、四十五、四十的序列被打乱重排，垂直方向也能看到四十四和四十五反复出现。修复方式是错开：把 X 投影垂直移动半个周期，X 和 Z 之间的重复就消失了；把 Z 投影水平移动半个周期，Y 和 Z 之间的重复也消失了；X 和 Y 本身不对齐，不用管。半周期是上限，如果贴图里只有三条明显的带状结构，三分之一会更好。地形贴图通常不关心精确对齐。
验证方法：把权重直接当反照率输出，看到的应该是一条平滑的混合带，而不是硬边。
里程碑五，法线贴图与 whiteout 混合。目标是让法线贴图真正贴合曲面。关键语义分三层。第一层是换轴和翻转：法线采样是切线空间的，先按投影方向换轴，再因为前面为了防镜像取负过 U，这里也要把切线法线的横轴取负，并且在上方向指向内侧的那些投影上把上方向翻转。第二层是混合：我没有逐投影归一化，而是写了一个不归一化的变体，横纵分量相加、竖直分量相乘，这就是 whiteout blending 的做法；它假设竖直轴朝上，所以要把表面法线先转换到各自的投影空间，混合完再转回世界空间。省掉三次归一化，是因为最后还要整体归一化一次。
第三层是一个修正。对朝向负方向的表面，whiteout 会把两个负的竖直分量相乘，最终符号被翻回来，结果是错的。修法有两种：用其中一个分量的绝对值，或者干脆一开始就不把采样的竖直分量取负。我选了后一种，把那段取负的代码删掉，等价但更干净。还有一个备选叫 UDN 混合，完全放弃采样的竖直分量，只用原始的表面分量，在用压缩法线贴图时更便宜，因为它不需要重建竖直分量，代价是非对齐表面的法线强度会被削弱。
验证方法：把反照率临时换成法线，球体上的凹凸应该跟着表面弯曲，而不是像立方体那样一个面一个方向。
再往后就是调参，而调参是这条链路真正花时间的地方。权重在归一化之前依次经过偏移、饱和、取幂，再乘上高度插值的结果。偏移的作用是同时削弱所有权重，小的更吃亏，混合区因此变窄；不饱和的话负权重会从结果里减掉数据，所以要在归一化之前夹住；指数是非线性地进一步收窄，范围到八，默认是二；高度则让贴图自己的蓝色通道参与竞争。高度这里有个上限要注意，强度用插值控制，范围到零点九九而不是一，因为满强度会把某些权重彻底归零。偏移的上限也有限制，理论极限是三分之一开根号，大约零点五七七，实际取零点五，默认零点二五。验证方法还是把权重当颜色看，偏移越高，混合区越窄。
顶部贴图是在这上面加的一个特性：一组额外的顶部贴图，一个着色器关键字，只在表面朝上时用顶部贴图覆盖 Y 投影的数据。典型的地形网格所有法线都朝上，这个判断可以直接省掉。按原图的效果，大理石顶部盖了一层电路，指数调到八之后过渡更利落。光照贴图则是加一个 meta 通道，把包含文件换成光照贴图版本，并声明它需要法线和世界位置。

【踩坑与边界】
坑一，法线贴图整体发蓝。症状是打开法线贴图后表面像盖了一层蓝膜。根因是切线空间被当成世界空间用，而竖直通道存的是局部上方向。修复是按投影换轴，而不是把三个采样直接相加。
坑二，颜色修好了，法线还在镜像。症状是反照率正常了，凹凸却是反的。根因是只对 UV 取了负，切线法线没有跟着取负。修复是把同样的取负条件复制到法线贴图上。
坑三，负朝向表面的法线又被翻回来。症状是背对画面的那些面，凹凸方向是相反的那一侧。根因是 whiteout 里两个负的竖直分量相乘。修复是不对采样的竖直分量取负。
坑四，编译器不合并解包。症状是开了顶部贴图之后，法线解包次数没有减少，带来额外的编译或性能开销。根因是着色器编译器能用条件分支聪明地只采样一次，但它不认为两次法线解包可以合并。修复是先把原始法线采样出来，选完贴图之后只解包一次。
坑五，光照贴图烘焙后全黑。症状是把对象设为静态、灯光切到烘焙，场景视图切到烘焙反照率，所有用了三平面映射的物体都是黑的。根因是没有 meta 通道，或者 meta 通道还在用光照包含文件。修复是加 meta 通道，换成光照贴图包含文件，并声明需要法线和世界位置。这两个宏还可以让其它用途跳过不必要的计算，不需要法线或者位置时用常量顶替。
还有几条版本和平台上的边界。meta 通道里 Unity 没有提供物体到世界的变换矩阵，所以光照贴图实际上是在对象空间算的，结果只对位于原点、没有旋转和缩放的物体正确。典型地形没问题，其它物体只有在材质统一、顶部对齐的情况下才勉强可用。整张打包属性贴图必须关掉 sRGB 导入，否则高度数据是错的。贴图属性要加上不显示平铺和偏移的修饰，因为缩放和平移对三平面没有太大意义；我只留一个整体缩放。最后是成本，三倍采样是硬开销，把金属度、遮蔽、高度、光滑度打包进一张贴图不是技巧，是必需。

【收束】
三句话：没有 UV 时，世界位置就是坐标，投影三次比展 UV 便宜；三平面映射的难点不在投影，在混合；混合靠法线权重，靠换轴和 whiteout 把法线贴回曲面，靠偏移、指数和高度调出想要的过渡。什么时候用：程序化几何体、运行时地形、洞穴这类没有 UV 的曲面，并且能接受三倍采样。什么时候不用：表面轴对齐、图案需要精确对齐，或者移动端采样预算已经很紧的场合。下一期我把镜头拉回光照本身，聊一聊实时光和烘焙光在同一张表面上怎么共存。
